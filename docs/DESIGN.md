# RowLog 設計

要件は `REQUIREMENTS.md`。ここを変えるときも先に要件を確認する。

---

## 1. 全体構成

```
[部員のスマホ]
   index.html 1枚（GitHub Pages / 公開・氏名を含まない）
        |
        | fetch (JSON)
        v
[Google Apps Script ウェブアプリ]  ← 名簿とメニューを返す / 回答を受ける
        |
        v
[Googleスプレッドシート]  名簿 / メニュー / 回答
[Googleドライブ]          写真
```

**常駐サーバーを持たない。** ryuのPCが落ちていても動く。

依存は最小にする。フロントはビルド無しの素の HTML/CSS/JS 1ファイル。
フレームワークもバンドラも使わない。6週間で終わる収集に、壊れる部品を増やさない。

## 2. データモデル（スプレッドシート）

### 「名簿」シート（Apps Script が読む。公開しない）

| 列 | 例 | 備考 |
|---|---|---|
| research_id | `C22` | 主キー |
| name | 山田 太郎 | 選択画面の表示用 |

### 「メニュー」シート

### 「予定表」シート（部の予定。主務が直接編集する）

**これが無いと欠測を数えられない。** 休養日なのか出し忘れなのかが区別できなくなる。

| 列 | 例 | 備考 |
|---|---|---|
| date | `2026-09-08` | 主キー |

### 「予定」シート（部員が出す翌日以降の予定。1提出＝1行）

| 列 | 型 | 備考 |
|---|---|---|
| submitted_at | ISO日時 | |
| research_id | 文字列 | |
| date | `YYYY-MM-DD` | 対象日。**今日より後だけ** |
| block_ids | カンマ区切り | |
| note | 文字列 | |
| client_id | UUID | 冪等キー |

同じ (research_id, date) を出し直したら**上書き**する（予定は変わるものなので履歴を持たない）。

## 3. API（Apps Script）

1つのウェブアプリで受ける。`?action=` で分岐。

| action | メソッド | 返すもの |
|---|---|---|
| `bootstrap` | GET | 名簿（active のみ）+ メニュー + 予定表 + サーバー日付 |
| `submit` | POST | 実績を1行追記。`{ok:true}` / 重複なら `{ok:true, duplicate:true}` |
| `plan` | POST | 予定を1行。同じ (research_id, date) なら上書き |
| `mine` | GET | 指定 research_id の直近45日分の実績と予定（カレンダーの●表示用） |
| `today` | GET | 指定日の提出状況（「みんな」タブ用）。研究用IDと出したかどうかだけ |
| `extract` | POST | v1.1。画像を受けて `{distance, split, rate, drag}` |

CORS: Apps Script のウェブアプリは `Access-Control-Allow-Origin` を自前で付けられないため、
**POST は `Content-Type: text/plain` にしてプリフライトを起こさない**。JSON は本文に文字列として入れる。
これは Apps Script の定番の回避策。

## 4. 画面

4画面だけ。増やさない。

### 画面は4タブ

| タブ | 中身 |
|---|---|
| 今日 | その日の実績を出す。上に「練習／オフ／大会」と予定メニューを出す |
| カレンダー | 月表示。**未来の日を押すと予定の入力、今日と過去の日を押すと実績の入力** |
| みんな | その日の提出状況。誰がまだ出していないかを主務が追える |
| 設定 | 名前の変更、送信待ちの件数 |

オフの日は参加状態が「休養」で最初から選ばれ、1タップで終わる。

### S1 初回設定
学年 → クラス → 氏名 の3タップ。選んだ research_id を localStorage に保存。

### S2 提出（メイン）
1画面で完結させる。スクロールは1〜2画面まで。

```
  9月8日（火）                     [日付を変える]
  ─────────────────────────
  今日は？
  [ 実施 ] [ 一部実施 ] [ 欠席 ] [ 休養 ]

  ── 実施 or 一部実施 のときだけ以下を出す ──

  練習時間        [  95  ] 分
  きつさ（RPE）
     今日の練習全体は、どのくらいきつかったですか
     0 —————●————— 10        6 きつい

  メニュー（任意）  [ + 選ぶ ]
     25分×2（b2） ×    エルゴダウンとマットダウン ×

  完了度   [計画どおり] [短縮] [中止] [変更]

  エルゴをやった   [ はい / いいえ ]
     ── はい のときだけ ──
     [ 写真を撮る ]  ← v1.1。撮ると下が自動で埋まる
     距離 [ 5106 ] m   split [ 1:57.5 ]   rate [ 25 ]
     ドラッグ [ 125 ]  機体 [ 3号 ]

  ひとこと（任意） [                    ]

           [   出す   ]
```

- RPEは**スライダーではなく0〜10のボタン**にする。スマホで片手で押せる。数字の下に言葉を出す
- 質問文は要領と同じ文言を画面に固定表示する。言い方を変えると答えが変わるため
- 「出す」を押したら即座に完了画面へ。送信はバックグラウンド（オフラインキュー）

### S3 完了
「出しました」＋直近7日の提出状況（●出した / ○まだ）。連続提出日数を出す。

### S4 設定
名前の変更、送信待ちの件数、アプリ版、代理入力モード。

## 5. オフライン対応

艇庫は電波が悪い。**送信できなくても入力が消えない**ことを最優先にする。

1. 「出す」を押したら、まず localStorage のキューに積む（client_id を採番）
2. すぐ完了画面を出す（送信の成否を待たせない）
3. バックグラウンドで送信を試みる。失敗したらキューに残す
4. 次回起動時・オンライン復帰時に再送
5. 同じ client_id は Apps Script 側で1行しか書かない（二重送信の防止）

## 6. 写真読み取り（v1.1）

```
写真 → 縮小(長辺1600px, JPEG) → Apps Script → Gemini API → JSON → 画面に反映（編集可）
```

- 抽出するのは **サマリ行の4つだけ**（距離・平均split・平均rate・ドラッグファクター）。
  スプリット全行は v1 では取らない。Phase 0 の実測で **サマリ行は81/81読めた**ので確度が高い
- 検算: `距離 / 時間` と `split` が ±0.5秒/500m で一致するかを**コード側**で確認し、
  合わないフィールドは黄色にして人に確認させる
- **読み取りは補助であって関門にしない。** 失敗しても手入力で先に進める
- 写真そのものは必ずドライブに残す。後から一括で読み直せる

Phase 0（`notes\2026-08-29-ErgShot-Phase0-抽出精度実測.md`）で分かった注意点:
- rate は最大54まで出る。上限40で弾くと短距離インターバルが全滅する
- Total Time は休憩を含む。漕いだ時間はサマリ行のほう
- 合計には1〜2の丸め誤差が出る

## 7. 技術判断の記録

| 決めたこと | 理由 |
|---|---|
| ビルド無しの HTML 1枚 | 依存が増えるほど壊れる。6週間で終わる収集に必要ない |
| Apps Script + スプレッドシート | 無料・常駐不要・そのまま解析に使える。38人が同時に押しても捌ける量 |
| 氏名をリポジトリに置かない | GitHub Pages は公開。名簿は Apps Script 経由で取る |
| RPEをボタンにする | スライダーは片手で正確に選べない。0〜10なら11個のボタンで足りる |
| 欠席時に時間とRPEを聞かない | 0を入れさせると「0分やった」と区別できなくなる |
| client_id で冪等にする | 電波の悪い場所での再送で二重計上しないため |
| Tailscale を使わない | 38人に入れてもらうのは非現実的 |
