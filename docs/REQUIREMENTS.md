# RowLog 要件定義

**凍結: 2026-08-31 ユーザー承認済み**
**改訂: 2026-08-31 予定提出を取り込み、元の部活マネージャーを引退させる方針に変更（ユーザー承認済み）**
以後この内容を変えるときは必ずユーザーに確認する。

---

## 1. 目的

慶應義塾高校端艇部の部員が、毎日の練習後に「どれだけやったか」と「どれくらいきつかったか」を記録する。
卒業研究のデータ収集を兼ねる。アウトカムは9月上旬と10月下旬の20分エルゴ。

**成功の定義**: 6〜8週間、38名の記録が欠測少なく集まり、そのまま解析にかけられる形で残ること。
アプリの機能が多いことではない。

---

## 2. 利用者と端末

| | |
|---|---|
| 利用者 | 2年14名 + 1年24名 = **38名**（3年6名は引退のため対象外） |
| 端末 | 各自のスマートフォン（iOS / Android）のブラウザ。ホーム画面に追加して使う |
| 入力者 | **各自が自分で入力する**。RPEは本人の感覚なので代理入力は原則しない |
| 例外 | 出し忘れた人の分を、記録係が後から代理入力できる。その場合は入力者を記録に残す |
| 管理者 | 主務（ryu）1名 |

---

## 3. 入力（1回の提出で出すもの）

| 項目 | 形式 | 必須 | 備考 |
|---|---|---|---|
| 日付 | 自動（当日）。前日以前も選べる | ○ | |
| 参加状態 | 実施 / 一部実施 / 欠席 / 休養 | ○ | 「休養」と未提出を区別するために必須 |
| 練習時間 | 分（整数） | ○ | 参加状態が実施・一部実施のときだけ |
| RPE | 0〜10 の整数 | ○ | 同上。練習終了15〜30分後に答える |
| メニュー | 39ブロックから複数選択 | × | 既存の部活マネージャーの辞書をそのまま使う |
| 完了度 | 計画どおり / 短縮 / 中止 / 変更 | ○ | 同上 |
| ひとこと | 自由記述（任意、200字まで） | × | |

### エルゴをやった日だけ追加で

| 項目 | 形式 | 備考 |
|---|---|---|
| 距離 | m（整数） | |
| 平均split | 文字列（例 `1:57.5`） | |
| 平均rate | 整数 | |
| ドラッグファクター | 整数 | |
| 機体番号 | 文字列 | |
| PM画面の写真 | 画像（複数可） | v1.1 で自動読み取り |

**欠席・休養を選んだときは、練習時間とRPEを聞かない。** 0を入れさせない。

---

## 4. 出力

Googleスプレッドシートに1提出＝1行。列は `docs/DESIGN.md` の「回答シート」に定義。

**シートに氏名は一切書かない。** 研究用ID（B01 / C14 など）だけを書く。

---

## 5. 頻度と量

- 1人1日1件。練習が2部あっても1日1件にまとめる（練習時間を合算し、RPEは全体で1つ）
- 38名 × 45日 ≒ **1,700件**。スプレッドシートで十分扱える量
- 写真は6週間で数百枚を見込む

---

## 6. コスト

**全部無料の範囲でやる。**

| | |
|---|---|
| 画面の置き場所 | GitHub Pages（無料） |
| データの受け口 | Google Apps Script ウェブアプリ（無料） |
| データの保存先 | Googleスプレッドシート（無料） |
| 写真の保存先 | Googleドライブ（無料枠） |
| 写真の読み取り | Gemini API の無料枠（v1.1）。**課金は設定しない** |

サーバーを常駐させない。ryuのPCが落ちていても動く。

---

## 7. 本人確認

**名前を選ぶだけ。** パスワードもPINも置かない。

- 初回起動時に学年→クラス→氏名の順で選ぶ
- 選んだら端末に記憶し、2回目以降は選ばなくてよい
- 設定画面から選び直せる

なりすましは技術的に防がない。部内アプリであり、なりすます動機が無いため。
入力の摩擦を1秒でも減らすことを優先する。

---

## 8. 個人情報の扱い

**氏名を公開リポジトリに置かない。**

GitHub Pages は公開なので、名簿をフロントのコードに埋め込むと38名の実名が公開される。
名簿は Apps Script 経由でスプレッドシートから取得する。リポジトリには名前を一切含めない。

| データ | 置き場所 |
|---|---|
| 氏名・ふりがな | スプレッドシートの「名簿」シートのみ |
| 研究用IDと氏名の対応 | `box\2026-08-31-研究用ID対応表.xlsx` とスプレッドシートの「名簿」シート |
| 解析に流すデータ | 研究用IDのみ。氏名なし |
| 保護者名・最寄駅・出身中学・アレルギー | **アプリでは一切扱わない** |

---

## 8-2. 予定の提出（改訂で追加）

部員が翌日以降の練習で「何をやるつもりか」をメニューから選んで出す。
既存の部活マネージャーが持っていた機能を RowLog に取り込み、**元アプリは引退させる**。

理由: 部員が毎日2つのアプリを開くと、片方が使われなくなる。開く場所を1つにする。
副次的に、予定と実績が同じ場所に並ぶので「計画どおりできたか」が自動で比較できる。

- カレンダーで**未来の日**を押すと予定の入力、**今日と過去の日**を押すと実績の入力になる
- 予定は日付＋メニュー（複数）＋ひとこと。参加状態・RPE・練習時間は聞かない
- 実績を出すとき、その日の予定メニューが最初から入った状態で始まる

## 8-3. 部の予定表（改訂で追加）

その日が **練習 / オフ / 大会・テスト** のどれかを持つ。**これが無いと欠測を数えられない**
（休養日だから出していないのか、練習日なのに出し忘れたのかが区別できない）。

- 部員は読むだけ。オフの日は参加状態が「休養」で最初から選ばれる
- **主務がスプレッドシートの「予定表」シートを直接編集する。** 管理画面はアプリに作らない

## 9. スコープ外（作らない）

後で「あれも」と言われないよう先に書いておく。

- ログイン機能・パスワード
- コーチ用のダッシュボード・グラフ・ランキング
- 通知・リマインダー（v1では作らない。運用でカバーする）
- 出欠管理・連絡機能
- 水上練習の艇・クルー・ポジションの記録
- 心拍数
- **管理画面**（予定表・名簿・メニューの編集はスプレッドシートで直接やる。主務1人しか使わないので画面を作る価値がない）
- 既存の部活マネージャーの改修（ソースが無いため触れない。引退させる）

---

## 10. リリース段階

収集開始を遅らせないため2段階で出す。使う人の操作は変わらない。

| 版 | 時期 | 内容 |
|---|---|---|
| **v1.0** | 9月頭 | 手入力で収集開始。エルゴ結果も手で打つ |
| **v1.1** | 9月中旬 | 写真を撮ると距離・split・rateが自動で入る。**読み取り結果は必ず人が直せる。失敗しても手入力で進める** |

v1.0 を出した時点で収集が始まる。v1.1 は差し替えるだけで、使う人の作業は増えない。

---

## 11. 決まっていないこと

- 20分エルゴの実施日（9月上旬・10月下旬のいつか）
- エルゴの台数と組分け
- Gemini API キーの取得（v1.1 の直前でよい）
